# G502 X LIGHTSPEED onboard editor

This experimental editor targets Windows and the direct USB-cable route `046d:c098`. It uses HID++ feature `0x8100`; it does not pretend the mouse implements the office-mouse reprogrammable-controls feature `0x1b04`.

## Supported operations

- Read and back up all user-memory sectors without changing execution mode.
- Edit a profile name, five DPI stages, default/DPI-shift stages, and 125/250/500/1000 Hz report rate.
- Edit normal and G-Shift bindings: mouse buttons, keyboard-page keys with modifiers, media keys, and known firmware actions.
- Preserve untouched bindings, existing macro references, name encodings and unknown bytes.
- Explicitly switch host/onboard mode and activate or reload an enabled profile without programming flash.
- Validate/export a draft, write one profile with a durable backup and exact readback, and restore an applied edit through the CLI.

The desktop has a profile selector, assignment workspace, sensitivity page, memory-management page and persistent save/discard footer. It communicates only through the agent. The agent retains the device lease through the complete transaction even if the IPC requester disconnects. All three application binaries must use the same IPC protocol version.

While this mouse is in onboard mode, background host-DPI reconciliation yields to the firmware. Explicit host-DPI requests report that the onboard editor must be used instead; other devices retain their existing path.

After writing a profile, select **Activate / reload profile** to load its settings into the mouse. Saving an inactive profile does not switch away from the currently active profile.

## Boundaries

Only formats memory/profile/macro `1/(3 or 5)/1` with 255/256-byte sectors are editable. Unsupported routes and formats fail explicitly. Bad CRCs, stale full-memory captures, invalid settings, duplicate assignments and removal of the last ordinary left-click are rejected. Writes are not retried after uncertain transport outcomes. The process guard is best-effort exclusion of G HUB/Options settings processes, not a system-wide lock against future opens.

Button numbers are firmware indices, not claimed G HUB marketing labels or verified physical hotspots. This increment does not implement multi-step macro authoring/execution, foreground-application switching, enabling disabled slots, arbitrary backup import, or receiver-mode acceptance. Existing macro bytes are preserved.

The optional `tools/ghub_profile_export.py` reads assigned settings from G HUB's local SQLite database. It produces an inert migration inventory, does not access authentication or cloud APIs, and does not claim that exported macros or built-in IDs have been imported.

## Protocol provenance

Command framing, profile layout and CRC behavior were implemented from the reverse-engineered [libratbag HID++ implementation](https://github.com/libratbag/libratbag/tree/8235b5bb6032dea15901ab58a8218956f4494d08/src), particularly `hidpp20.c`, `hidpp20.h` and `hidpp-generic.c`. This is not a published Logitech specification. No G HUB UI artwork is included.

## Hardware verification

On 2026-10-09, a USB G502 X LIGHTSPEED reported formats 1/3/1, sixteen 255-byte sectors, five profiles and eleven button entries. Directory and profile CRC checks passed. A name-only edit to an inactive enabled profile was written and every byte read back, then restored. A subsequent full capture matched all sixteen original sectors byte-for-byte; mode and active profile were unchanged.

This verifies the observed sector transaction and restore path. It does not verify every assignment's physical behavior, wireless routes, mode switching or all firmware revisions. Synthetic tests cover bounds, stale-state rejection, left-click protection, preservation, frame sequencing, failed-transfer handling, keyboard encoding and GUI drafts. Windows native visual/physical-input acceptance of the redesigned workspace remains pending.

For a controlled repeat, close other settings software, make a fresh full backup, prepare a name-only edit to a verified inactive profile, apply it, restore it and compare a second full capture. Keep memory captures, local paths and migration inventories out of public contributions.
